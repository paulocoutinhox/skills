# Editorial validation without automation

This skill is descriptive. It does not bundle or create counting scripts, parsers or publishing automation.

Check the real final payload, including spaces, line breaks, hashtags, mentions, disclosures and links. Use the native publishing interface's counter and preview when you can. Tell apart code points, UTF-8 bytes, UTF-16 units and X weighted text. A raw string length is not exact evidence for every surface.

For YouTube tags, the commas between tags and the extra quote count for tags with spaces use up the budget. Tags and visible hashtags are different fields. For X, recognized URLs and supported emoji sequences have platform-specific weights. Do not guess an exact accepted count from how long the text looks.

If native checks are not available, state the field's researched limit and unit, explain what you checked by reading, and mark platform acceptance as unchecked. Do not build an implementation just to fake certainty. Check the final pasted text again after changes.

Read the copy as its audience will. Remove notes about how it was made, placeholders, labels such as "Caption:" inside the field text and any mention of AI, agents, tools or prompts that the user did not ask for. A platform-required AI disclosure goes in the platform's disclosure setting, and the package records it as a setting decision.

Record the field, surface, limit/unit and real check status in the delivery. Check links, spelling, factual claims, accessibility and disclosures separately from the character count. Neither a valid length nor a good preview proves that the message is accurate or persuasive.
