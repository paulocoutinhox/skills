# Social Post

Prepare copy that communicates a truthful, relevant promise to a specific audience. Adapt the content to each network's actual publishing surface. This skill is descriptive. It does not create counters, parsers, publishing scripts or automatic data updates.

## Start with positioning, not a formula

Collect the actual content/transcript, audience, language, situation, goal, brand voice, supported facts, offer, destination links and requested networks. Identify organic versus paid content and any disclosure obligations. Ask only for facts that materially change the result.

Write a short internal brief: who this is for, what problem they recognize, what useful outcome the content provides, what evidence demonstrates it, and what action makes sense next. “Everyone interested in technology” is usually too broad to guide vocabulary or relevance.

Compare alternatives the audience already uses, including doing nothing. Explain the specific benefit the actual content can support. Do not turn an unverified differentiator into “the best,” claim search volume without data, or invent urgency/testimonials/results.

April Dunford's [Obviously Awesome](https://www.aprildunford.com/books) is professional further reading on positioning, verified through the author's book description. Its B2B context should not be treated as an algorithmic law for creator posts. Chip and Dan Heath's [Made to Stick](https://heathbrothers.com/books/made-to-stick/) supplies useful further reading on understandable, memorable ideas. These frameworks guide questions and editorial judgment, not promised performance.

## Build the message

Choose one central promise the content fulfills. Lead with a concrete problem, result, demonstration or useful question. Put enough context in the opening that a reader understands the subject before a preview truncates. There is no universal character count for a visible first line across devices.

Connect claims to proof: an actual demonstration, example, source or observed result. Prefer specific useful language over vague adjectives. A curiosity gap should delay an answer the content really provides, not conceal the subject or exaggerate an outcome.

Use a primary action appropriate to the journey: watch the demonstration, save the procedure, read details, try a relevant workflow or answer a substantive question. Do not demand many unrelated actions or use empty engagement bait. Support scannability with meaningful paragraphs and deliberate emoji, not decorative clutter.

Localize the meaning, terminology, examples, units and context. Check accents, names, technical terms, timezone and right-to-left behavior where relevant. Literal translation can preserve words while losing the audience's actual problem.

## Native fields and researched ceilings

Baseline: 2026-11-05. These are the written research findings for their stated surfaces. Only update stored rules when the user requests maintenance. During an actual publishing task, confirm account/interface acceptance without silently rewriting this skill.

| Surface | Actual fields and researched ceiling | Editorial decision |
| --- | --- | --- |
| YouTube | Title 100 characters, Studio description 5,000 characters, Data API description 5,000 UTF-8 bytes, tags 500 under API comma/quote accounting | Match title, thumbnail and opening. Front-load subject and useful value |
| YouTube Shorts | Video title/description/tags with the same interface distinction | Align caption/title with the first actual visual/spoken moment. `#Shorts` is not required for classification |
| TikTok Direct Post video | API `title` is the caption, researched limit 2,200 UTF-16 units | Do not invent a separate native title/description field. App limits can differ |
| Instagram feed/Reel | Working caption ceiling 2,200, with hashtags/mentions inside it | Use up to five relevant hashtags as the conservative editorial profile, with account verification |
| X standard | 280 weighted characters | URL and Unicode weighting differ from visible text length. Longer products need actual account/surface confirmation |
| LinkedIn feed | Body 3,000 characters | A normal post has no separate native title, description or tag field |

Instagram's official live bodies were not reliably retrievable in the baseline research. Indexed API wording has historically described 30 hashtags/20 mentions, while current app guidance can restrict hashtags to five. Do not claim one universal limit across every interface. State uncertainty and use the conservative profile until the exact account/interface is confirmed.

The YouTube Data API rejects `<` and `>` in title/description. Tags are separate from hashtags. Tags containing spaces have additional quote accounting, and separating commas consume budget. More than 60 YouTube hashtags causes hashtags on that content to be ignored, which is not a recommendation to approach 60.

## Produce a complete package

For YouTube/Shorts, supply the title, unique description, actual tags, hashtags in their chosen visible field, optional pinned comment and creative support text separately. Ask about category, content language, visibility/schedule/timezone, made-for-kids status, paid promotion and synthetic-content disclosure when applicable. Timestamps/chapters require the actual media, not invented sections.

For TikTok, supply the final caption including selected tags/mentions, optional cover/on-screen text and spoken hook as creative support, plus applicable privacy/comment/duet/stitch decisions. For Instagram, supply caption, included tags/mentions, supported alt text, Reel cover text and any requested location/collaboration/product disclosure fields actually available.

For X, supply each final post and image alt text separately. Use a thread only when it adds substance or the user requests it. For LinkedIn, supply the body, supported media alt text and any optional first comment as a separate artifact. Articles, newsletters, ads and link previews have different contracts.

Do not label non-native creative copy as an API field. Do not fill every network with the same text. Use [the output template](assets/post-package.md) while removing irrelevant surfaces.

## Worked adaptation

Assume the supplied demo genuinely shows a reading-notes app organizing notes and finding them locally without uploading them. It does not show cloud sync or measurable time savings. The following is an illustrative direction, not invented product evidence:

- YouTube title: “Find Your Reading Notes Without Uploading Them.” The description opens with the demonstrated local organization/search workflow, then explains the actual steps and verified destination link. The thumbnail can show a genuine organized-versus-scattered view if the demo supports it.
- Shorts/TikTok hook: “You wrote the note. Now find it without scrolling through every page.” It belongs beside the actual search demonstration. The caption names the workflow and one relevant action, without promising a feature absent from the edit.
- Instagram: describe the reader's problem, summarize the demonstrated organization method, and give a save-worthy takeaway. Add alt text describing meaningful visual content rather than repeating promotional copy.
- X: make one concrete observation about organizing/searching reading notes, explain the demonstrated distinction and include the relevant link if useful. Do not force a thread to maximize volume.
- LinkedIn: frame the practical information-retrieval problem, explain the workflow and its actual boundary, and invite a substantive discussion of note organization. Avoid claiming productivity statistics that were not measured.

The same facts produce different openings and structures. They do not authorize different factual claims.

## Validation without automation

Read the final pasteable text, including spaces, line breaks, hashtags, mentions, disclosure and links. Check spelling, claims, field fit, link destinations and accessibility. Use the native interface's counter/preview when available. Do not report an exact weighted count based only on visual length or ordinary string length.

Unicode units matter. An accented character can occupy multiple UTF-8 bytes, and an emoji can occupy multiple code points/UTF-16 units. X also treats recognized links and supported emoji sequences through platform-specific weighting. Explain the relevant unit and leave acceptance unverified if the actual interface is unavailable. Do not introduce a parser to simulate certainty.

Supply a field/limit/verification table. Distinguish an editorial draft, a checked final payload and actual published content. Recheck after editing. See [editorial validation](references/validation.md) and [platform detail](references/platforms.md).

## Measurement and delivery

Define a hypothesis, audience/surface, primary metric and observation window. CTR is clicks divided by eligible impressions, not views divided by followers. Pair click metrics with retention/watch time or the actual conversion goal. A high click rate with poor satisfaction may reflect a misleading promise.

Use comparable distribution or a supported randomized platform test where authorized. Do not declare a winner from a tiny sample, different audiences or sequential periods with changed promotion. Report uncertainty and downstream effects. No hook, hashtag count or posting schedule guarantees reach.

Deliver finished fields, the preferred variant and reason, relevant limits/verification status, and a small measurement plan. Preparing text does not authorize posting it.
