# Social Post

Write copy that makes an honest, relevant promise to a specific audience. Fit the content to each network's real publishing surface. This skill is descriptive. It does not create counters, parsers, publishing scripts or automatic data updates.

## Start with positioning, not a formula

Collect the real content/transcript, audience, language, situation, goal, brand voice, supported facts, offer, destination links and requested networks. Find out whether the content is organic or paid and whether any disclosure is required. Ask only for facts that would really change the result.

Write a short internal brief: who this is for, what problem they recognize, what useful outcome the content gives, what evidence shows it, and what action makes sense next. “Everyone interested in technology” is usually too broad to guide word choice or relevance.

Compare the options the audience already uses, including doing nothing. Explain the specific benefit the real content can back up. Do not turn an unchecked advantage into “the best,” claim search volume without data, or make up urgency/testimonials/results.

April Dunford's [Obviously Awesome](https://www.aprildunford.com/books) is professional further reading on positioning, checked through the author's book description. Its B2B context should not be treated as an algorithm rule for creator posts. Chip and Dan Heath's [Made to Stick](https://heathbrothers.com/books/made-to-stick/) is useful further reading on ideas that are easy to understand and remember. These frameworks guide your questions and editorial judgment. They do not promise performance.

## Build the message

Choose one central promise the content keeps. Open with a concrete problem, result, demonstration or useful question. Put enough context in the opening that a reader understands the subject before a preview cuts it off. There is no single character count for a visible first line across devices.

Tie claims to proof: a real demonstration, example, source or observed result. Prefer specific, useful words over vague adjectives. A curiosity gap should hold back an answer the content really gives. It should not hide the subject or exaggerate an outcome.

Use one main action that fits the journey: watch the demonstration, save the procedure, read details, try a relevant workflow or answer a real question. Do not ask for many unrelated actions or use empty engagement bait. Make the text easy to scan with meaningful paragraphs and emoji used on purpose, not decorative clutter.

Write the final copy as natural content addressed to the audience. Do not describe how it was made, introduce it as a caption or draft, or mention AI, agents, tools or prompts unless the user asks for that. When a platform policy requires an AI or synthetic-content disclosure, record it as a decision for the platform's own setting, such as YouTube Studio's "AI use" attribute for realistic altered or synthetic media, not as text in the title, description or caption. Sponsorship and material-connection disclosures are different. They follow the law and platform tools that apply, and they can go in the copy.

Localize the meaning, terms, examples, units and context. Check accents, names, technical terms, time zone and right-to-left behavior where they matter. A literal translation can keep the words but lose the audience's real problem.

## Native fields and checked limits

Baseline: 2026-11-05. These are the written research findings for the surfaces named. Update stored rules only when the user asks for maintenance. During a real publishing task, confirm what the account/interface accepts without quietly rewriting this skill.

| Surface | Real fields and checked limit | Editorial decision |
| --- | --- | --- |
| YouTube | Title 100 characters, Studio description 5,000 characters, Data API description 5,000 UTF-8 bytes, tags 500 under API comma/quote accounting | Match title, thumbnail and opening. Put the subject and useful value first |
| YouTube Shorts | Video title/description/tags with the same interface difference | Match the caption/title to the first real visual/spoken moment. `#Shorts` is not required for classification |
| TikTok Direct Post video | API `title` is the caption, researched limit 2,200 UTF-16 units | Do not make up a separate native title/description field. App limits can differ |
| Instagram feed/Reel | Working caption limit 2,200, with hashtags/mentions inside it. Instagram announced a gradual cap of five hashtags per post or Reel caption | Use up to five relevant hashtags and confirm the account's current behavior |
| X standard | 280 weighted characters | URL and Unicode weighting differ from visible text length. Longer products need confirmation on the real account/surface |
| LinkedIn feed | Body 3,000 characters | A normal post has no separate native title, description or tag field |

For Instagram, treat five hashtags per post or Reel caption as the working maximum. How that gradual cap is enforced can differ by account, interface and API surface, so say so when the exact surface is not confirmed.

The YouTube Data API rejects `<` and `>` in title/description. Tags are separate from hashtags. Tags with spaces count extra for quotes, and the commas between tags use up the budget. More than 60 YouTube hashtags makes YouTube ignore all hashtags on that content. That is not a suggestion to get close to 60.

## Produce a complete package

For YouTube/Shorts, give the title, a unique description, real tags, hashtags in the visible field you chose, an optional pinned comment and creative support text, each separately. Ask about category, content language, visibility/schedule/time zone, made-for-kids status, paid promotion and the "AI use" disclosure when it applies. YouTube requires that disclosure for realistic altered or synthetic content, not for production help such as AI help with a script, title or thumbnail. Timestamps/chapters need the real media, not made-up sections.

For TikTok, give the final caption including the chosen tags/mentions, optional cover/on-screen text and spoken hook as creative support, plus the privacy/comment/duet/stitch decisions that apply. For Instagram, give the caption, included tags/mentions, supported alt text, Reel cover text and any requested location/collaboration/product disclosure fields that really exist.

For X, give each final post and image alt text separately. Use a thread only when it adds substance or the user asks for one. For LinkedIn, give the body, supported media alt text and any optional first comment as a separate item. Articles, newsletters, ads and link previews have different contracts.

Do not label non-native creative copy as an API field. Do not fill every network with the same text. Use [the output template](assets/post-package.md) and remove surfaces that do not apply.

## Worked adaptation

Say the supplied demo really shows a reading-notes app organizing notes and finding them locally without uploading them. It does not show cloud sync or measurable time savings. Below is a sample direction, not made-up product evidence:

- YouTube title: “Find Your Reading Notes Without Uploading Them.” The description opens with the local organize/search workflow shown in the demo, then explains the real steps and the checked destination link. The thumbnail can show a real organized-versus-scattered view if the demo supports it.
- Shorts/TikTok hook: “You wrote the note. Now find it without scrolling through every page.” It goes next to the real search demonstration. The caption names the workflow and one relevant action, without promising a feature that is not in the edit.
- Instagram: describe the reader's problem, sum up the organization method shown and give a takeaway worth saving. Add alt text that describes the meaningful visual content instead of repeating promotional copy.
- X: make one concrete point about organizing/searching reading notes, explain the difference shown and include the relevant link if useful. Do not force a thread just to post more.
- LinkedIn: frame the practical problem of finding information, explain the workflow and its real limit, and invite a real discussion of note organization. Do not claim productivity numbers that nobody measured.

The same facts lead to different openings and structures. They do not allow different factual claims.

## Validation without automation

Read the final text you will paste, including spaces, line breaks, hashtags, mentions, disclosure and links. Check spelling, claims, field fit, link destinations and accessibility. Remove any description of how it was made, or any mention of AI, agents, tools or prompts, that the user did not ask for. Use the native interface's counter/preview when you can. Do not report an exact weighted count based only on how long the text looks or an ordinary string length.

Unicode units matter. An accented character can take several UTF-8 bytes, and an emoji can take several code points/UTF-16 units. X also gives recognized links and supported emoji sequences their own platform-specific weights. Explain the unit that applies, and mark acceptance as unchecked if the real interface is not available. Do not add a parser to fake certainty.

Give a field/limit/check table. Keep an editorial draft, a checked final payload and real published content apart. Check again after editing. See [editorial validation](references/validation.md) and [platform detail](references/platforms.md).

## Measurement and delivery

Define a hypothesis, audience/surface, main metric and observation window. CTR is clicks divided by eligible impressions, not views divided by followers. Pair click metrics with retention/watch time or the real conversion goal. A high click rate with low satisfaction may mean the promise was misleading.

Use comparable distribution or a supported randomized platform test where approved. Do not declare a winner from a tiny sample, different audiences or back-to-back periods with changed promotion. Report uncertainty and later effects. No hook, hashtag count or posting schedule promises reach.

Deliver the finished fields, the preferred variant and why, the limits that apply and their check status, and a small measurement plan. Preparing text is not permission to post it.
