# Sources and rule ownership

Verified: 2026-11-05. Check version-specific APIs again when working in a concrete repository.

- [uv projects](https://docs.astral.sh/uv/guides/projects/) and [Ruff](https://docs.astral.sh/ruff/): Python environment, lint, and formatting tools.
- [Swift ARC](https://docs.swift.org/swift-book/documentation/the-swift-programming-language/automaticreferencecounting/) and [Swift 6 concurrency](https://developer.apple.com/documentation/swift/adoptingswift6): ownership and isolation. The full bodies were verified through the official [ARC documentation data](https://docs.swift.org/swift-book/data/documentation/the-swift-programming-language/automaticreferencecounting.json) and [concurrency Markdown](https://developer.apple.com/documentation/swift/adoptingswift6.md) after the JavaScript frontends proved unsuitable for static reading.
- [Android architecture recommendations](https://developer.android.com/topic/architecture/recommendations) and [Kotlin coroutines](https://kotlinlang.org/docs/coroutines-basics.html): state flow, lifecycle, layering, and structured concurrency.
- [C++ Core Guidelines](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines) and [clang-format options](https://clang.llvm.org/docs/ClangFormatStyleOptions.html): resource ownership, concurrency, and formatter controls.
- [Rust ownership](https://doc.rust-lang.org/book/ch04-01-what-is-ownership.html), [error handling](https://doc.rust-lang.org/book/ch09-00-error-handling.html), and [shared-state concurrency](https://doc.rust-lang.org/book/ch16-03-shared-state.html): ownership, explicit failures, and synchronization boundaries. [Cargo lockfiles](https://doc.rust-lang.org/cargo/guide/cargo-toml-vs-cargo-lock.html), [test selection](https://doc.rust-lang.org/cargo/commands/cargo-test.html), and [Clippy usage](https://doc.rust-lang.org/clippy/usage.html) support the verification workflow. Warning configuration must match the selected Cargo version.
- [Lua reference manual index](https://www.lua.org/manual/) and [Lua 5.5 manual](https://www.lua.org/manual/5.5/manual.html): current standard-language baseline, values, modules, errors, resource cleanup, and host integration. [StyLua documentation](https://github.com/JohnnyMorganz/StyLua) and [Luacheck CLI](https://luacheck.readthedocs.io/en/stable/cli.html) document formatter/linter behavior. The reviewed tool support lists do not establish Lua 5.5 syntax coverage. Confirm the concrete release and target before prescribing either tool.
- [CommonMark](https://spec.commonmark.org/), [GFM specification](https://github.github.com/gfm/), and [GitHub code-block guidance](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/creating-and-highlighting-code-blocks): Markdown syntax, extension boundaries, sanitization, and fenced examples. [Markdownlint](https://github.com/DavidAnson/markdownlint) supplies configurable style checks rather than a separate universal syntax standard.
- [Thinking in React](https://react.dev/learn/thinking-in-react), [Vue state management](https://vuejs.org/guide/scaling-up/state-management.html), [Angular style guide](https://angular.dev/style-guide), and [Vite](https://vite.dev/guide/): component responsibility, state choices, filenames, and tooling.

MVVM defaults, helper naming, one type per file, empty Python initializers, no `TYPE_CHECKING`, no anonymous C++ namespaces, class-owned C++ functions, and lambda format guards are owner conventions. They are not universal requirements imposed by the languages. Safe language or framework exceptions are stated in each profile.

## Professional foundation and evidence scope

Reviewed for this revision: 2026-11-05. [Python task cancellation](https://docs.python.org/3/library/asyncio-task.html), [React effects](https://react.dev/learn/you-might-not-need-an-effect), [Vue watcher cleanup](https://vuejs.org/guide/essentials/watchers.html), [Angular RxJS interoperability](https://angular.dev/ecosystem/rxjs-interop) and the [Rust async chapter](https://doc.rust-lang.org/book/ch17-00-async-await.html) support the applied lifecycle cases. Roberto Ierusalimschy's [Programming in Lua](https://www.lua.org/pil/) is further reading with an explicit edition/runtime boundary. The fourth edition covers Lua 5.3, so it does not supersede the selected current manual.
