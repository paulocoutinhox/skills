## Formatter width settings

Verified: 2026-11-18. The [clang-format options](https://clang.llvm.org/docs/ClangFormatStyleOptions.html) define `ColumnLimit: 0` as no column limit, under which input line breaks inside statements are respected. `BreakAdjacentStringLiterals` was introduced in clang-format 18. clang-format 23.1.2 was run locally: `--dump-config` reported limits of 80 for LLVM, Google, Chromium and Mozilla, 79 for GNU, 120 for Microsoft and 0 for WebKit. It joined a wrapped call under a positive wide limit, preserved it under a zero limit, and failed with `unknown key` on an unsupported configuration key. [Ruff settings](https://docs.astral.sh/ruff/settings/) document the default `line-length` of 88. Local Ruff runs confirmed that a wide width alone does not join a call with a magic trailing comma, while `skip-magic-trailing-comma` does and emits an isort incompatibility warning unless `split-on-trailing-comma` is disabled. [Prettier options](https://prettier.io/docs/options) describe `printWidth`, default 80, as a target rather than a hard limit. The [rustfmt configuration reference](https://github.com/rust-lang/rustfmt/blob/master/Configurations.md) documents stable `max_width` (100), `fn_call_width` (60) and `use_small_heuristics = "Max"`. StyLua's `column_width` default of 120 is described in its documentation. Swift-format, SwiftLint and ktlint width keys must be confirmed in the pinned tool version.

The [npm 12.0.0 release notes](https://github.com/npm/cli/releases/tag/v12.0.0), checked 2026-11-18, state that dependency lifecycle scripts are blocked by default unless allowed by the root package's `allowScripts` policy, approved with `npm install-scripts approve` and executed with `npm rebuild`.

MVVM defaults, helper naming, one type per file, empty Python initializers, no `TYPE_CHECKING`, no anonymous C++ namespaces, class-owned C++ functions, lambda format guards, and single-line calls with a wide formatter width are owner conventions. They are not universal requirements imposed by the languages. Safe language or framework exceptions are stated in each profile.
